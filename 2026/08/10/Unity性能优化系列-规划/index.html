Unity 性能优化系列·写作规划

Created2026-08-10|Updated2026-08-13|写作规划
|Post Views:

系列定位

名称：Unity 性能优化七讲

目标读者：有 1-3 年 Unity 经验的开发者，能读代码、有基本 Profiler 概念，但缺乏系统性优化方法论。

篇幅标准：单篇 3000-5000 字，可独立阅读，合起来构成完整体系。

写作原则：

  • 每篇必须有”从问题到修复”的完整链路（建数据 → 定位 → 改 → 验证）
  • 代码示例完整可运行，不做伪代码
  • 优先使用 Unity 2022.3 LTS+ API，标注版本差异
  • 每篇末尾附 checklist，方便读者自查项目

篇目总览

阅读顺序建议：1→2→3 是核心三件套，4/5/6 可按需跳读，7 贯穿始终可先看。

第1讲：CPU 与脚本优化 ✅ 已完成

为什么放在第一讲：CPU 瓶颈是开发者日常最常遇到的，也是最容易”写出性能问题的层”。

大纲

  1. CPU 性能模型速览（500字）

    • 主线程 vs 渲染线程 vs Job 线程
    • PlayerLoop 结构图（前 15 帧剖面）
    • 什么时候 CPU 是瓶颈？（GPU 等 CPU vs CPU 真忙）

  2. Update 模式：隐形成本大户（800字）

    • 空 Update 的真实代价（IL2CPP 下不会消除，C++ 虚表调用链）
    • 降频策略：自实现简易 Timer/Interval
    • 分帧策略：用协程或 IEnumerator 分摊负载
    • 何时用 FixedUpdate / LateUpdate，何时不该用

  3. GameObject 与 Component 操作（700字）

    • GameObject.Find / Transform.Find 的代价与缓存策略
    • GetComponent 在 Update 里 vs 启动时缓存（benchmark 数据）
    • SendMessage / BroadcastMessage 的反射开销 → 改用接口或事件
    • Instantiate / Destroy 的位置与策略

  4. 物理与动画（500字）

    • Physics.Simulate 的 Fixed Timestep 调整
    • 碰撞体复杂度：MeshCollider 的代价
    • Animator 的 UpdateMode 与 Culling Mode
    • Playable API 替代传统 Animation 的收益

  5. Job System + Burst 入门（600字）

    • 何时值得上 Job（> 1000 元素、纯数据运算）
    • IJobParallelFor 最小示例（含 benchmark）
    • Burst 的魔法与限制（不能 new 对象、不能调托管代码）

  6. 实战案例（400字）

    • 场景：1000 个敌人 AI 寻路每帧 Update 卡顿
    • Profile → 定位 → 分帧 + Job System → 验证

现有材料复用

  • 优化总结.md “编程和代码框架” 部分（Update/字符串/NonAlloc）

需补充研究

  • PlayerLoop 详细结构
  • Job System benchmark 数据
  • Animator CullingMode 各档的实际性能差异

第2讲：GPU 与渲染优化 ✅ 已完成

为什么第二讲：CPU 解决了就得看 GPU，很多”卡”其实在 GPU 端。

大纲

  1. 渲染管线速览与 GPU 瓶颈判断（500字）

    • Unity 渲染管线：CPU 提交 → GPU 顶点 → 片元 → 输出
    • 怎么判断是 GPU bound？（Profiler Gfx.WaitForPresent vs Camera.Render）
    • 移动端 vs PC 端的 GPU 瓶颈差异

  2. DrawCall 与 Batcher（1000字）

    • DrawCall 为什么会贵（状态切换、CPU→GPU 通信）
    • 静态 Batching：原理、条件、内存代价（标记 BatchingStatic）
    • 动态 Batching：条件严苛（顶点 < 300、相同材质）、通常不可靠
    • SRP Batcher（重点）：原理（per-object 大 CBUFFER）、条件、迁移步骤
    • GPU Instancing：适用场景与限制

  3. Shader 优化（600字）

    • Shader Variant 爆炸：#pragma multi_compile vs shader_feature
    • ShaderVariantCollection 预热
    • 移动端慎用 discard、clip（早-Z 失效）
    • 精度选择：half vs float 在移动端的真实收益

  4. 几何与可见性（500字）

    • LOD：配置策略、过渡距离、LOD Group 开销
    • 遮挡剔除：原理、烘焙步骤、动态物体的处理
    • 视锥剔除：Unity 自动做，别自己再做一遍

  5. 光照与后处理（400字）

    • Forward vs Deferred 的选择
    • 烘焙/混合光照策略
    • 阴影：分辨率、距离、级联数
    • Post Processing：Bloom 的 GPU 代价、移动端裁剪建议

  6. 实战案例（400字）

    • 场景：大世界场景 DrawCall 3000+ → 落到 200 以内
    • 步骤：Frame Debugger → 标记静态 → SRP Batcher → 合并材质 → 验证

现有材料复用

  • 优化总结.md “图形和GPU” 部分
  • 游戏GPU性能优化.md 链接和笔记

需补充研究

  • SRP Batcher 与静态 Batching 的混合使用策略
  • 各平台 Shader 精度 benchmark
  • URP vs Built-in 的渲染差异

第3讲：内存管理与 GC ✅ 已完成

为什么第三讲：内存和 GC 是”最不直观”的瓶颈——代码看起来没问题，但帧率有规律地掉。

大纲

  1. Unity 内存模型（500字）

    • 托管内存（Mono/IL2CPP） vs 原生内存（引擎资源）
    • 堆 vs 栈：值类型分配在哪？
    • GC 触发时机：堆阈值、System.GC.Collect、场景加载

  2. 分配热点排查（800字）

    • Profiler Memory 模块：GC.Alloc 列
    • 常见隐形分配：
      • foreach 在旧版 Unity 的分配（新版已修复，需标注版本）
      • LINQ / Enumerable.Range
      • 字符串拼接（+ / String.Format / $）
      • 闭包与匿名方法捕获
      • 协程的 new WaitForSeconds（应缓存）
      • GetComponent<T>() 返回 List/Array 的 API
      • Debug.Log 在生产构建中的残留

  3. 减少分配的设计模式（700字）

    • 对象池：ObjectPool<T>（Unity 2021+ 内置）vs 自实现
    • NonAlloc 系列 API：Physics.OverlapSphereNonAlloc
    • 缓存 WaitForSeconds、WaitForEndOfFrame
    • StringBuilder 缓存与清除
    • struct 正确使用姿势：小而不可变、不装箱

  4. GC 调优（400字）

    • Incremental GC（Unity 2019+）的工作原理与注意事项
    • 手动 GC.Collect 的时机（场景切换）
    • IL2CPP 下的 GC 差异

  5. 内存泄漏检测（400字）

    • Memory Profiler 使用流程
    • 常见泄漏源：静态引用、事件未退订、OnDestroy 未清理
    • DontDestroyOnLoad 的双刃剑

  6. 实战案例（400字）

    • 场景：每 5 秒规律性卡顿 50ms
    • Profile → 发现 2MB/frame GC.Alloc → 逐行追踪 → 修复 LINQ + 字符串 → 验证到 2KB/frame

现有材料复用

  • 优化总结.md “编程和代码框架” 中 NonAlloc/GC 部分

需补充研究

  • IL2CPP vs Mono GC 行为差异
  • Unity 2022 LTS 的 Incremental GC 数据
  • 常见 API 的分配量 benchmark 表

第5讲：资源与资产管理 ✅ 已完成

为什么第五讲：资源是”配置即性能”的典型——不改代码，只改导入设置就能大幅提性能。

大纲

  1. 资源三大阶段：导入 → 加载 → 卸载（400字）

    • 资源全生命周期模型
    • 哪个阶段的问题最常见？

  2. 纹理优化（800字）

    • Max Size：没 UI 的纹理不要 > 1024
    • POT vs NPOT（2的幂）
    • 压缩格式选择矩阵（ASTC/ETC2/DXTC/不压缩）
    • MipMap：何时开、何时关
    • Read/Write Enabled 的 2x 内存惩罚
    • Sprite Atlas：打包策略（按场景/按功能？）

  3. 网格与动画优化（500字）

    • Mesh Compression 选项
    • 顶点属性优化：UV2/Tangent 的按需开关
    • BlendShape 的内存代价
    • Animation Clip 压缩（Keyframe Reduction）
    • Animator Controller 的 Layer 开销

  4. 音频优化（300字）

    • 加载类型：Decompress On Load vs Streaming
    • 压缩格式与比特率
    • 强制单声道

  5. 加载策略：AssetBundle vs Addressables（700字）

    • AssetBundle 基础工作流（过时但仍有项目在用）
    • Addressables 的优势：引用计数、远程加载、分组策略
    • 加载 vs 预加载 vs 异步加载
    • Resources 文件夹的陷阱
    • 引用计数管理与 Addressables.Release

  6. 实战案例（400字）

    • 场景：首场景加载 8 秒 → 1.5 秒
    • 步骤：纹理压缩 + 音频格式 + 拆分 Addressables 分组 + 预加载热资源

现有材料复用

  • 优化总结.md “资源内存” 和 “音频” 部分

需补充研究

  • Addressables 分组策略的最佳实践
  • 各纹理压缩格式在各平台的文件大小/memory 对比
  • Unity 6 Addressables 新特性

第6讲：C# 语言层优化 ✅ 已完成

为什么第六讲：前面五讲偏 Unity 引擎，这一讲回归语言底层——很多分配和 CPU 问题根源在 C# 代码。

大纲

  1. 值类型 vs 引用类型（700字）

    • struct 分配在栈？——不对，是”看上下文”
    • struct 的陷阱：装箱（接口调用、object 参数、ArrayList）
    • 何时用 struct：小（< 16 bytes）、不可变、短生命周期
    • readonly struct 和 ref struct 的意义
    • 典型错误：把 struct 当 class 用

  2. 集合选择（600字）

    • List<T> vs Array：Capacity 预分配
    • Dictionary<TKey, TValue> 的内部实现与碰撞
    • HashSet<T> vs List<T> 查找对比
    • 避免 ArrayList、Hashtable（遗留的装箱陷阱）
    • .NET 新集合：ArrayPool<T>、Span<T>、ReadOnlySpan<T>

  3. Span<T> 与 Memory<T>（500字）

    • Span 是什么（栈上的类型安全指针）
    • 替代 string.Substring 的零分配方案
    • 操作数组切片而不复制
    • 限制：不能作为类字段、不能装箱

  4. LINQ 的代价（400字）

    • Where + Select 链：每次迭代的 delegate 调用
    • .ToList() / .ToArray() 的额外分配
    • 何时 LINQ 是可接受的（初始化阶段）
    • 替代方案：for / foreach + if

  5. 字符串与格式化（400字）

    • 字符串是不可变的 → 每次拼接都分配
    • StringBuilder 缓存技巧（Clear() 而非 new）
    • string.Format vs $ 插值（编译结果相同）
    • string.Intern 的应用场景
    • StringComparison.Ordinal 比 CurrentCulture 快

  6. unsafe 与指针（200字）

    • 何时值得用：大量数组操作、与 native 交互
    • 风险与收益

  7. 实战案例（400字）

    • 场景：战斗伤害数字每帧生成 200+ 个 string → 100KB GC/frame
    • 修复：StringBuilder 缓存 + SetText("{0}", value) → 接近零分配

现有材料复用

  • 无现有材料覆盖

需补充研究

  • BenchmarkDotNet 跑一组自带数据的对比（List vs Array, LINQ vs for, string 操作）
  • Unity IL2CPP 下 Span<T> 的支持情况
  • System.Text.StringBuilder 在 Unity 中的可用性
