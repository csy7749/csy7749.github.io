游戏AI-寻路算法 系列·写作规划

Created2026-08-13|Updated2026-08-18|写作规划
|Post Views:

系列定位

名称：游戏AI-寻路算法（从 A* 出发）

目标读者：写游戏逻辑、想自己实现或调优寻路的开发者；以及想理解 Unity NavMesh / GOAP Planner 背后图搜索原理的人。

核心思路：以 A* 为锚点，向基础（BFS / Dijkstra）和进阶（JPS / Flow Field / NavMesh）两个方向扩展。每篇可独立阅读，但共享同一套“图搜索”视角和术语。

写作原则：

  • 先讲“为什么需要它、它解决什么问题”，再给算法流程，最后给完整可运行代码
  • 代码可直接运行验证，不做伪代码
  • 网格寻路统一用“格子 = 节点、相邻格 = 边、代价 = 步长”的模型
  • 每篇末尾附“自查清单”

篇目总览

阅读顺序建议：想快速上手直接看第 1 讲；想补齐理论基础看 2、3；做性能优化或大量单位看 4、5；结合引擎落地看 6。

第1讲：A* 寻路 ✅ 已完成

为什么放在第一讲：A* 是游戏寻路的事实标准，也是理解其他寻路算法（Dijkstra、JPS、Flow Field）的基准。

大纲

  1. 寻路的本质：把地图看成图
  2. A* 核心公式 f(n) = g(n) + h(n)
  3. 启发函数：曼哈顿 / 切比雪夫 / 欧几里得 / Octile
  4. 可采纳性与一致性：为什么能保证最优
  5. 算法流程（伪代码 + 流程图）
  6. 完整可运行的 Python 实现
  7. 与 BFS / Dijkstra / 贪心最佳优先的对比
  8. 网格寻路的工程细节（8 方向、穿墙、tie-breaking、堆）
  9. 复杂度、适用场景与 Unity 落地
  10. 自查清单

第2讲：BFS / DFS 与无权图搜索（计划中）

为什么需要它：先搞懂“无权的图怎么搜”，A* 里的扩展、Open/Closed 概念才不悬空。

大纲（草案）

  1. BFS 的队列与逐层扩散
  2. DFS 的回溯与适用边界
  3. 为什么 BFS 在无权图上天然最短
  4. 从 BFS 到 Dijkstra 的一步之遥

第3讲：Dijkstra 与带权图最短路径（计划中）

为什么需要它：A* 去掉启发函数就是 Dijkstra，理解它才能理解“代价”如何进入搜索。

大纲（草案）

  1. 带权边与最短路径问题
  2. 优先队列驱动的 Dijkstra
  3. 为什么不能处理负权边
  4. Dijkstra 到 A* 的演进

第4讲：JPS（Jump Point Search）（计划中）

为什么需要它：在均匀网格上，A* 会探索大量“等价”节点，JPS 通过跳点剪枝大幅减少搜索。

大纲（草案）

  1. 均匀网格的对称性
  2. 跳点的定义与剪枝规则
  3. JPS 与 A* 的差异
  4. 何时值得用 JPS

第5讲：Flow Field（流场寻路）（计划中）

为什么需要它：大量单位涌向同一目标时，逐单位 A* 太贵，流场把“每个单位的寻路”摊薄成“一次全局计算”。

大纲（草案）

  1. 从“单个路径”到“整场方向场”
  2. 距离场与梯度
  3. 流场的生成与更新
  4. 大量单位协同移动的集成

第6讲：NavMesh 与寻路的工程落地（计划中）

为什么需要它：把算法接回引擎，看看 Unity NavMesh 是怎么组织图、怎么处理动态障碍和局部绕行的。

大纲（草案）

  1. NavMesh 的图模型：多边形与边
  2. A* 在导航网格上的变体
  3. 动态障碍与局部避让
  4. 自定义寻路与 NavMesh 的边界
