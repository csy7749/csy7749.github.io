Unity Shader（5）：顶点与片元着色器——语义、内置函数与宏

Created2026-08-13|Updated2026-08-18|UnityShader
|Post Views:

前几讲我们一直在”读结构”，这一讲进入手写 Shader 的语法地基。顶点/片元着色器的代码，本质就是几类东西：语义（Semantics）、数据类型、数学函数、采样函数，以及 Unity 提供的一堆内置宏。把这几类”词汇表”过一遍，后面写光照、纹理、特效时就不会再对着代码发懵。

一、输入输出结构体：appdata 与 v2f

一个典型的顶点/片元着色器，数据是这样流动的：

两个结构体的命名只是约定（URP 里习惯叫 Attributes 和 Varyings），真正起作用的是冒号后面的语义。

二、语义：GPU 认”标签”不认”名字”

语义（Semantics）是 HLSL 里告诉 GPU”这个字段装的是什么数据”的标记。字段名可以随便起，语义不能乱用。

2.1 输入语义（顶点着色器读取）

语义 含义
POSITION 顶点位置（模型空间）
NORMAL 顶点法线（模型空间）
TANGENT 顶点切线（模型空间，float4，最后一位是手性）
TEXCOORD0 ~ TEXCOORD3 UV 坐标 / 自定义数据通道
COLOR 顶点颜色

2.2 输出/系统语义

语义 含义
SV_POSITION 顶点着色器必须输出的裁剪空间坐标
SV_Target 片元着色器输出的最终颜色
SV_DispatchThreadID Compute Shader 的全局线程编号
SV_VertexID 顶点索引（高级用法）

带 SV_ 前缀的是系统语义（System-Value），由硬件直接消费，不能随便挪作他用。例如 v2f 里必须有一个字段用 SV_POSITION 承载裁剪空间位置，否则光栅化无法进行。

三、数据类型与精度

3.1 标量与向量

访问分量用 .xyzw（空间含义）或 .rgba（颜色含义）混用都行，如 v4.rgb、v4.xy。

3.2 精度怎么选

  • 颜色、低精度插值：用 half / fixed，移动端省带宽。
  • 位置、世界坐标、法线方向等需要精度的量：用 float。
  • 经验法则：能省则省，位置相关别省。移动端把”颜色”用 float 计算是常见浪费。

3.3 矩阵

HLSL 的 mul(m, v) 会把 v 当列向量处理；写错顺序会导致结果错误，这是新手高频坑。

四、常用数学函数

Shader 里几乎所有效果都是这些函数的组合：

函数 作用 示例
normalize(v) 归一化（长度变 1） 法线必须归一化
dot(a, b) 点积（两向量夹角余弦 × 长度积） 光照、投影
cross(a, b) 叉积（求垂直向量） 求切线/副切线
length(v) 向量长度 距离判断
lerp(a, b, t) 线性插值 颜色/数值过渡
saturate(x) 夹到 [0,1] 防止越界
clamp(x, a, b) 夹到 [a,b] 范围限制
step(edge, x) x≥edge 返回 1，否则 0 硬边缘
smoothstep(a, b, x) 平滑过渡 软边缘、抗锯齿
pow(x, y) 幂运算 高光指数
floor(x) / frac(x) 取整 / 取小数 网格、噪声
reflect(i, n) / refract(i, n, eta) 反射 / 折射方向 水面、玻璃
distance(a, b) 两点距离 距离场

其中 dot 是光照的灵魂：两个单位向量的点积，正好等于它们夹角的余弦，从 1（同向）到 -1（反向）。第 6 讲的光照就是靠 saturate(dot(N, L)) 算出来的。

五、采样函数

  • Built-in：tex2D(_MainTex, uv)，返回该 UV 处采样出的 fixed4 颜色。
  • URP：SAMPLE_TEXTURE2D(_MainTex, sampler_MainTex, uv)（配合 TEXTURE2D/SAMPLER 声明）。

采样前 UV 通常是 float2，采样后得到 RGBA 颜色，再接 * _Color 或 lerp 做混合。

六、Unity 内置宏与变量

Unity 把大量常用操作封装成了宏，不同管线名字略有差别：

6.1 坐标与方向变换

Built-in URP 作用
UnityObjectToClipPos(v) TransformObjectToHClip(v) 模型空间 → 裁剪空间
UnityObjectToWorldDir(d) TransformObjectToWorldDir(d) 模型方向 → 世界方向
UnityObjectToWorldNormal(n) TransformObjectToWorldNormal(n) 模型法线 → 世界法线
UnityWorldSpaceViewDir(pos) GetWorldSpaceViewDir(pos) 求视线方向
UnityWorldSpaceLightDir(pos) GetMainLight().direction 等 求光照方向（URP 差异大）

6.2 内置矩阵

现代写法推荐用 unity_ObjectToWorld 和 UnityObjectToClipPos，UNITY_MATRIX_MVP 是老代码常见写法，看到要认识。

6.3 时间与参数

顶点动画、溶解、流光等效果，基本都用 _Time.y（当前秒数）驱动。

七、头文件体系

  • Built-in：#include "UnityCG.cginc" 一个文件几乎包罗万象。
  • URP：拆成多个模块化头文件，按需引入：
URP 头文件 提供内容
Core.hlsl 坐标变换、基础宏
Lighting.hlsl 光照计算相关
Shadows.hlsl 阴影
Input.hlsl 输入与相机参数

八、自查清单

  • 能解释”字段名随意、语义不能乱用”
  • 能说出 POSITION / NORMAL / TEXCOORD0 / TANGENT / SV_POSITION / SV_Target 的含义
  • 知道 float / half / fixed 的精度差异与选择原则
  • 能写出 saturate(dot(N, L)) 并说出它算的是什么
  • 能说出 normalize / dot / cross / lerp / smoothstep 的用途
  • 知道 Built-in 与 URP 的坐标变换宏对应关系
  • 知道 _Time.y 常用于驱动动画
