Unity Shader（9）：常用效果实战——模型特效与业务 UI Shader

Created2026-08-13|Updated2026-08-18|UnityShader
|Post Views:

前面的语法学得差不多了，这一讲把它们串起来：先完成顶点动画、模型溶解和描边，再实现灰度按钮、能量条、UI 裁剪、UI 溶解以及三类流光。每个效果都给出代码、参数说明和常见坑，重点回答项目里“这个 Shader 为什么这样写”。

本文按 Unity 2022.3 LTS 的 Built-in ShaderLab 写法示例。后半部分补充项目里更常见的 UI/HUD 效果；灰度示例保留 Stencil，灰度、裁剪和溶解示例保留 RectMask2D 入口，其他效果可以按同一结构补上裁剪代码。

一、顶点动画：让模型”活”起来

1.1 原理

顶点动画的关键在于：在 vert 里移动顶点的位置。因为 vert 每帧、每个顶点都会执行，所以只要把位置写成时间的函数，模型就会动起来。

1.3 常见坑

  • 法线不会跟着动：顶点位置变了，但法线还是原来的，光照会显得”没变化”。真实水面/布料要么重算法线，要么用贴图遮一下，或者接受”无光照”效果。
  • 阴影不会跟着动：顶点动画发生在 Shader 里，阴影 Pass 用的是原始顶点。要让阴影也跟着动，需要自定义阴影投射 Pass（高级话题）。
  • 顶点动画适合顶点数量足够的网格，低模上波浪会很”块状”。

三、描边：法线外扩（Shell 方法）

3.1 原理

描边最常见的做法是”背面壳”：再画一个 Pass，把顶点沿法线方向往外扩一点，只显示背面，涂成描边色。因为壳比原模型略大，露出的边缘就成了描边。

3.3 常见坑

  • 硬边网格会断裂：沿顶点法线外扩要求”相邻面共享平滑法线”，硬边（不同法线）会在棱角处裂开。解决办法是烘焙平滑法线、或用顶点色控制描边宽度、或改用屏幕空间后处理描边。
  • 近大远小：固定世界单位外扩，远处描边会显得细。想做”屏幕恒定宽度”要用后处理描边。
  • 法线外扩 vs 屏幕空间：Shell 方法简单直观，但不稳定；屏幕空间描边（基于深度/法线做边缘检测）更稳定，属于后处理范畴——下一讲会讲。

四、灰度 Shader：不可点击按钮的禁用态

4.1 业务场景与原理

按钮被禁用时，通常要同时做到两件事：交互层把 interactable 设为 false，渲染层把图标和文字降为灰度。Shader 只负责后者，不能代替 Button.interactable，否则视觉状态和点击逻辑会脱节。

灰度值使用感知亮度近似公式：0.299R + 0.587G + 0.114B。_GrayScale 为 0 时保留原色，为 1 时完全灰度，方便做状态过渡。

4.3 参数与坑

  • 禁用态建议由 C# 或状态机驱动 _GrayScale。UGUI 不适合用 MaterialPropertyBlock 做逐元素参数，应该复用一份禁用材质，或在状态初始化时创建并缓存材质实例；不要每帧 new Material。
  • 灰度只改变 RGB，保留原始 Alpha，因此不会破坏圆角、图标镂空和 CanvasGroup 的透明度。
  • 如果按钮仍然能点击，问题在 EventSystem/interactable，不是 Shader。

五、进度条 Shader：能量条与冷却条

5.1 原理

进度条的核心是比较 UV 与进度值：step(uv.x, _Progress) 得到左侧填充区域。用 smoothstep 在边界保留极窄的软边，可以减少低分辨率 UI 上的锯齿。下面的 Shader 把背景色和填充色放在一个 Pass 中，适合血条、经验条和技能冷却能量条。

5.2 完整代码

_Progress 应由业务数据归一化到 [0,1] 后写入；不要把百分比整数直接传给 Shader。若要从右向左填充，把比较值改为 1 - i.uv.x，或增加一个方向枚举。多根能量条共用同一 Material 时会共用 _Progress；需要不同进度就缓存各自的材质实例，或者优先使用 Image.fillAmount，避免制造大量材质和批次。

六、UI 裁剪：RectMask2D 与自定义矩形裁剪

UGUI 的 RectMask2D 最终也是把局部坐标与 _ClipRect 比较。Shader 必须声明 UNITY_UI_CLIP_RECT 相关入口，否则 UI 在编辑器里看似被裁剪，换成自定义材质后可能穿透遮罩。这个版本只保留裁剪逻辑，适合作为其他 UI 特效的基线。

真正使用 RectMask2D 时，Unity 会自动设置 _ClipRect。如果是自己传矩形，约定为 (xmin, ymin, xmax, ymax) 的 UI 局部坐标；不要把屏幕坐标和局部坐标混用。

七、溶解 Shader：头像、卡牌和 UI 弹出效果

前面的模型溶解使用同样的 clip 思路，这里只把输入换成 UI UV，并加入 UGUI 裁剪。_Dissolve 从 0 增加到 1 时，噪声值较低的区域先消失；边缘区用 _EdgeColor 点亮，能明显看出溶解正在发生。

噪声贴图建议关闭 sRGB，并使用单通道灰度图；否则颜色空间转换会改变阈值分布，导致同一个 _Dissolve 在不同平台看起来不一致。

八、边缘流光：卡牌选中态与可交互提示

边缘流光只在 UI 四条边附近产生高光，不会把整张卡牌照白。border 是到最近边的距离，phase 是沿 UV 的移动相位；两者相乘后，流光始终被限制在边框区域。

这是低成本的 UV 近似流光，不是严格的矩形周长参数化；如果边框必须沿四边连续转圈，应在 C# 预计算周长 UV，或改用一张边框流光贴图。

九、斜向流光：奖励、稀有度和按钮 Hover

斜向流光用 uv.x + uv.y 定义一条斜线，随着 _Time.y 平移。_ShineWidth 控制带宽，_ShineColor 使用加法叠加，所以底图颜色和透明度仍由原图决定。

移动端上不要把 _ShineWidth 调得过小；亚像素宽度会闪烁。若只需要播放一次，把 _Time.y 换成业务传入的归一化进度，动画生命周期会更容易控制。

十、UI 流光：通用的横向高光扫过

“UI 流光”通常指一条从左到右扫过整个图标或按钮的高光带，与斜向流光的区别是它沿单一 UV 轴移动，适合新道具提示、可领取状态和加载完成反馈。下面用 smoothstep 做柔和带状遮罩。

这类动画通常只在对象可见时播放：进入屏幕时启用流光材质，完成一次扫光后把强度归零或换回静态材质，减少持续的片元计算和透明 Overdraw。_Time 驱动的 Shader 不会触发 Canvas Rebuild，但 Canvas 每帧绘制时仍会执行这些像素计算。若项目使用 URP，ShaderLab 的 Blend/Cull/ZWrite 仍然相同，只需要把 UnityCG.cginc 的顶点变换替换为 Core.hlsl 与 TransformObjectToHClip。

效果 关键输入 常见业务 主要风险

落地时优先确认三件事：动画参数由谁驱动、材质是否被多个 UI 共用、效果是否需要支持 Mask/RectMask2D。把这些边界先定清楚，比继续堆叠更多数学函数更能避免线上 UI 状态错乱。
