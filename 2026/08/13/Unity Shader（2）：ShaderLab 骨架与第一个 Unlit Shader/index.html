Unity Shader（2）：ShaderLab 骨架与第一个 Unlit Shader

Created2026-08-13|Updated2026-08-17|UnityShader
|Post Views:

上一讲我们拿到了”全局地图”，这一讲开始动手读代码。Unity 的 .shader 文件由两部分语言拼成：外层是描述结构的 ShaderLab，内层是真正跑在 GPU 上的 HLSL/CG。本文逐层拆开 Shader / SubShader / Pass 的骨架，并把一个最简 Unlit Shader 每一行都讲清楚。学完这篇，Unity 菜单里 Create → Shader 生成的模板你就能看懂结构了。

一、ShaderLab 的三层结构

打开任何一个 .shader 文件，你会看到它像一个”套娃”。最外层是 Shader，往里是 SubShader，再往里是 Pass：

Shader "路径/名称"
├── Properties        ← 材质面板上可调的参数
├── SubShader          ← 一组"渲染方案"（可写多个，按平台/能力择优）
│   ├── Tags           ← 渲染队列、类型等标签
│   ├── LOD / 其他状态
│   └── Pass           ← 一次完整的渲染流程（可写多个）
│       ├── 状态开关（Cull / ZWrite / Blend…）
│       └── HLSL / CG 代码块
└── Fallback           ← 所有 SubShader 都不适用时退回的兜底
```text

三个层级的分工：

- **Shader**：整个文件的入口，`"路径/名称"` 是它在材质下拉菜单里的显示名。
- **SubShader**：一套完整的渲染实现。为什么要多个？因为高端平台和低端平台可能需要不同复杂度的实现，Unity 会从上到下找到第一个"当前设备能用"的 SubShader。
- **Pass**：一次实际渲染。一个 SubShader 可以包含多个 Pass，物体就会被画多次（这正是描边、多光源等效果的基础）。

## 二、Properties：暴露到材质面板的参数

`Properties` 里声明的变量，会出现在材质（Material）面板上，供美术/策划调参；同时它们会以 `_变量名` 的形式在代码里被访问。

```hlsl
Properties
{
    _MainTex ("Base (RGB)", 2D) = "white" {}
    _Color   ("Tint Color", Color) = (1,1,1,1)
    _Amount  ("Amount", Range(0, 1)) = 0.5
    _Speed   ("Speed", Float) = 1.0
    _Mask    ("Mask", Cube) = "" {}
}
```text

语法结构是：`变量名 ("面板显示名", 类型) = 默认值`。常见类型：

| 类型 | 说明 | 默认值示例 |
| :--- | :--- | :--- |
| `Float` | 单精度浮点 | `= 1.0` |
| `Range(min, max)` | 滑杆 | `= 0.5` |
| `Color` | 颜色（RGBA） | `= (1,1,1,1)` |
| `Vector` | 四维向量 | `= (0,0,0,0)` |
| `2D` | 2D 纹理，默认值 `"white"` | `= "white" {}` |
| `3D` | 3D 纹理 | `= "" {}` |
| `Cube` | 立方体贴图 | `= "" {}` |

注意两个常见约定：
- 变量名必须以 `_` 开头（如 `_Color`），这是 Unity 的命名习惯。
- 纹理默认值后面的 `{}` 是纹理采样/导入设置的占位，普通写法照抄即可。

## 三、SubShader 与 Tags

每个 SubShader 通常先写一组 `Tags`，用键值对声明这个 SubShader 的"身份"：

```hlsl
SubShader
{
    Tags { "RenderType"="Opaque" "Queue"="Geometry" }
}
```text

最常用的两个 Tag：

| Tag | 作用 | 常见值 |
| :--- | :--- | :--- |
| `RenderType` | 声明渲染类型，供替换 Shader 时分类 | `Opaque` / `Transparent` / `TransparentCutout` |
| `Queue` | 指定渲染队列（决定绘制顺序） | `Background` / `Geometry` / `AlphaTest` / `Transparent` / `Overlay` |

`Queue` 是透明渲染的核心，第 8 讲会专门展开。现在你只需记住：**不透明物体默认画在 Geometry 队列，半透明要放到 Transparent 队列**。

## 四、Pass 里的状态开关

`Pass` 内部在写代码之前，可以先设置一组"渲染状态"，它们控制这个 Pass 怎么处理几何体和像素：

| 状态 | 作用 | 常见值 |
| :--- | :--- | :--- |
| `Cull` | 剔除哪一面 | `Back`（默认，剔除背面）/ `Front` / `Off` |
| `ZWrite` | 是否写入深度缓冲 | `On`（默认）/ `Off` |
| `ZTest` | 深度测试方式 | `LEqual`（默认）/ `Less` / `Always` |
| `Blend` | 颜色混合方式 | `SrcAlpha OneMinusSrcAlpha` 等 |
| `ColorMask` | 写入哪些颜色通道 | `RGB` / `RGBA` / `0` |

这些"开关"决定了一个 Pass 的画法，后面讲到透明、描边、水面时会反复用到。

## 五、CGPROGRAM / HLSLPROGRAM：代码块的分工

真正跑在 GPU 上的代码写在代码块里：

```hlsl
Pass
{
    CGPROGRAM
    // ... 这里是 CG/HLSL 代码
    ENDCG
}
```text

- `CGPROGRAM ... ENDCG`：内置管线时代的经典写法，里面是 CG 语言（语法和 HLSL 几乎一致）。
- `HLSLPROGRAM ... ENDHLSL`：URP / HDRP 下的推荐写法，里面是纯 HLSL。

两者的**角色边界**很重要：ShaderLab（外层）负责"结构和状态"，CG/HLSL（内层）负责"顶点/片元的计算逻辑"。

## 六、LOD 与 Fallback

- **LOD**：声明这个 SubShader 的复杂度等级。你可以配合 C# 的 `Shader.globalMaximumLOD` 在低端设备上强制用低 LOD 的实现。

```hlsl
SubShader { LOD 100 }  // 高 LOD = 更复杂
SubShader { LOD 50 }   // 低 LOD = 更简单
```text

- **Fallback**：如果所有 SubShader 都不被当前设备支持，就退回到另一个 Shader 的名字。它通常写成：

```hlsl
Fallback "Diffuse"
```text

写 `Fallback Off` 表示不退回。新手建议保留一个内置兜底（如 `"Diffuse"` 或 `"VertexLit"`），避免某些平台渲染不出东西。

## 七、逐行解析：第一个 Unlit Shader

下面是一个最简、可运行的 Unlit（无光照）着色器。它做的事很简单：采样一张纹理，乘上一个可调颜色。

```hlsl
Shader "Tutorial/FirstUnlit"
{
    Properties
    {
        _MainTex ("Base (RGB)", 2D) = "white" {}
        _Color   ("Tint Color", Color) = (1,1,1,1)
    }

    SubShader
    {
        Tags { "RenderType"="Opaque" "Queue"="Geometry" }
        LOD 100

        Pass
        {
            CGPROGRAM
            #pragma vertex vert
            #pragma fragment frag
            #include "UnityCG.cginc"

            struct appdata
            {
                float4 vertex : POSITION;
                float2 uv     : TEXCOORD0;
            };

            struct v2f
            {
                float2 uv     : TEXCOORD0;
                float4 vertex : SV_POSITION;
            };

            sampler2D _MainTex;
            float4 _MainTex_ST;
            fixed4 _Color;

            v2f vert (appdata v)
            {
                v2f o;
                o.vertex = UnityObjectToClipPos(v.vertex);
                o.uv = TRANSFORM_TEX(v.uv, _MainTex);
                return o;
            }

            fixed4 frag (v2f i) : SV_Target
            {
                fixed4 col = tex2D(_MainTex, i.uv) * _Color;
                return col;
            }
            ENDCG
        }
    }

    Fallback "Diffuse"
}
```text

### 7.1 两个 pragma：指定入口函数

```hlsl
#pragma vertex vert
#pragma fragment frag
```text

这两行告诉编译器：顶点着色器入口是名为 `vert` 的函数，片元着色器入口是名为 `frag` 的函数。函数名可以自己起，但必须和 pragma 对上。

### 7.2 include：引入内置宏

```hlsl
#include "UnityCG.cginc"
```text

`UnityCG.cginc` 里定义了 `UnityObjectToClipPos`、`TRANSFORM_TEX`、`_Time` 等大量内置宏和变量。**不 include 它，`UnityObjectToClipPos` 这类宏就无法使用**。

### 7.3 appdata：顶点输入

```hlsl
struct appdata
{
    float4 vertex : POSITION;
    float2 uv     : TEXCOORD0;
};
```text

- `POSITION` 语义告诉 GPU："`vertex` 这个字段接的是顶点位置"。
- `TEXCOORD0` 语义接第一套 UV 坐标。
- 这些字段的值由 Unity 在调用 `vert` 前自动填充。

### 7.4 v2f：从顶点着色器传到片元着色器

```hlsl
struct v2f
{
    float2 uv     : TEXCOORD0;
    float4 vertex : SV_POSITION;
};
```text

- `SV_POSITION` 是系统语义，必须用它承载"裁剪空间坐标"，光栅化阶段就靠它定位。
- `uv` 会被硬件自动插值后再传给 `frag`。

### 7.5 变量声明：和 Properties 对应

```hlsl
sampler2D _MainTex;
float4 _MainTex_ST;
fixed4 _Color;
```text

- `_MainTex` 和 `_Color` 与 `Properties` 里声明的名字一致，Unity 会自动把材质面板上的值填进来。
- `_MainTex_ST` 是 Unity 自动生成的变量：`.xy` 是 Tiling（平铺），`.zw` 是 Offset（偏移），正好供 `TRANSFORM_TEX` 使用。

### 7.6 顶点着色器

```hlsl
v2f vert (appdata v)
{
    v2f o;
    o.vertex = UnityObjectToClipPos(v.vertex);   // 模型空间 → 裁剪空间
    o.uv = TRANSFORM_TEX(v.uv, _MainTex);        // 应用 Tiling/Offset
    return o;
}
```text

- `UnityObjectToClipPos`：把顶点从模型空间一次性变换到裁剪空间，等价于老写法 `mul(UNITY_MATRIX_MVP, v.vertex)`。
- `TRANSFORM_TEX(v.uv, _MainTex)`：等价于 `v.uv * _MainTex_ST.xy + _MainTex_ST.zw`，让材质面板上的 Tiling/Offset 生效。

### 7.7 片元着色器

```hlsl
fixed4 frag (v2f i) : SV_Target
{
    fixed4 col = tex2D(_MainTex, i.uv) * _Color;
    return col;
}
```text

- `: SV_Target` 声明这个函数返回的是"该像素最终写入的颜色"。
- `tex2D(_MainTex, i.uv)`：按 UV 坐标采样纹理，得到纹素颜色。
- 乘上 `_Color` 得到最终颜色。因为 `_Color` 默认是白色 `(1,1,1,1)`，所以默认不影响纹理；把它调成其他颜色就相当于给贴图"染色"。

到这里，你已经完整看懂了一个 Shader 文件。后面所有效果，本质都是在 `vert` / `frag` 里加计算、在 `Properties` 里加参数、在 Pass 里改状态开关。
