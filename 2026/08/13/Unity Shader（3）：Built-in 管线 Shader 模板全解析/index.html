Unity Shader（3）：Built-in 管线 Shader 模板全解析

Created2026-08-13|Updated2026-08-17|UnityShader
|Post Views:

在 Unity 编辑器里右键 Create → Shader，会看到几个现成模板。很多人就是从”改模板”开始学 Shader 的，但如果不理解每个模板在干什么，很容易改崩。本文把 Built-in 管线下最常见的四个模板——Standard Surface Shader、Unlit Shader、Image Effect Shader、Compute Shader——逐一拆开，讲清它们的用途、生成代码的每一段，以及什么时候该选哪个。

一、模板清单与各自定位

不同 Unity 版本菜单略有差异，Built-in 管线下最常见的是这四种：

模板 生成入口 核心作用 适合
Standard Surface Shader Surface Shader 用”表面着色器”快速写光照材质 学光照、做普通材质
Unlit Shader Unlit Shader 最简的顶点/片元着色器 学 vert/frag、做无光照效果
Image Effect Shader Image Effect Shader 屏幕后处理的骨架 全屏效果、滤镜
Compute Shader Compute Shader GPU 通用计算 粒子、网格计算、大规模并行

四个模板覆盖了 Shader 的三种”形态”：表面着色器（Surface Shader）、顶点/片元着色器（Vertex/Fragment Shader）、计算着色器（Compute Shader）。Image Effect 本质上是特殊配置的顶点/片元着色器。

二、Standard Surface Shader：Unity 的”快速写法”

2.1 生成代码

Shader "Custom/NewSurfaceShader"
{
    Properties
    {
        _Color ("Color", Color) = (1,1,1,1)
        _MainTex ("Albedo (RGB)", 2D) = "white" {}
        _Glossiness ("Smoothness", Range(0,1)) = 0.5
        _Metallic ("Metallic", Range(0,1)) = 0.0
    }

    SubShader
    {
        Tags { "RenderType"="Opaque" }
        LOD 200

        CGPROGRAM
        #pragma surface surf Standard fullforwardshadows
        #pragma target 3.0

        sampler2D _MainTex;

        struct Input
        {
            float2 uv_MainTex;
        };

        half _Glossiness;
        half _Metallic;
        fixed4 _Color;

        void surf (Input IN, inout SurfaceOutputStandard o)
        {
            fixed4 c = tex2D (_MainTex, IN.uv_MainTex) * _Color;
            o.Albedo = c.rgb;
            o.Metallic = _Metallic;
            o.Smoothness = _Glossiness;
            o.Alpha = c.a;
        }
        ENDCG
    }

    FallBack "Diffuse"
}
```text

### 2.2 表面着色器是什么

关键是这一行：

```hlsl
#pragma surface surf Standard fullforwardshadows
```text

它的含义是：**使用 `Standard` 光照模型，表面数据由名为 `surf` 的函数提供**。你只需要写一个 `surf` 函数去"填充表面属性"（颜色、金属度、光滑度、法线等），Unity 会自动帮你生成完整的顶点着色器、片元着色器、光照计算、阴影和多光源 Pass。

换句话说，Surface Shader 是一种**语法糖**——它把大量模板代码藏了起来，让你专注在"这个表面长什么样"，而不是"光照怎么算"。

### 2.3 surf 函数与 SurfaceOutputStandard

```hlsl
void surf (Input IN, inout SurfaceOutputStandard o)
{
    fixed4 c = tex2D (_MainTex, IN.uv_MainTex) * _Color;
    o.Albedo = c.rgb;       // 基础色
    o.Metallic = _Metallic; // 金属度
    o.Smoothness = _Glossiness; // 光滑度
    o.Alpha = c.a;          // 透明度
}
```text

- `Input IN`：输入结构，Unity 根据字段名自动填充数据。
- `inout SurfaceOutputStandard o`：输出结构，你要往里面填表面属性。

`SurfaceOutputStandard` 的常用字段：

| 字段 | 含义 |
| :--- | :--- |
| `Albedo` | 基础颜色（漫反射颜色） |
| `Metallic` | 金属度（0=非金属，1=金属） |
| `Smoothness` | 光滑度（0=粗糙，1=镜面） |
| `Normal` | 法线（用 `UnpackNormal` 从法线贴图解出） |
| `Emission` | 自发光颜色 |
| `Alpha` | 透明度 |

### 2.4 Input 结构的命名魔法

`Input` 里的字段名不是随便起的，Unity 靠命名约定自动填充：

| 字段名 | 自动填充的内容 |
| :--- | :--- |
| `uv_纹理名` | 该纹理的 UV（如 `uv_MainTex`） |
| `uv2_纹理名` | 第二套 UV |
| `worldPos` | 世界坐标位置 |
| `worldNormal` | 世界空间法线 |
| `viewDir` | 视线方向 |
| `screenPos` | 屏幕坐标 |

例如 `float2 uv_MainTex;` 里的 `uv_` 前缀告诉 Unity："这是 `_MainTex` 的 UV"。这就是为什么上一讲手写的 Unlit 里用 `TRANSFORM_TEX`，而 Surface Shader 里直接用 `IN.uv_MainTex`。

### 2.5 什么时候用 Surface Shader

- **适合**：需要标准 PBR 光照的普通材质；快速原型；不想手写光照管线。
- **不适合**：需要精确控制 Pass 结构、做屏幕后处理、做不依赖光照的特效。这些场景直接写 vert/frag 更清晰。
- **注意**：Surface Shader 是 Built-in 的经典特性，URP 下虽然部分仍可用，但官方推荐手写 HLSL 或 Shader Graph。

## 三、Unlit Shader：最纯粹的 vert/frag 骨架

Unlit 模板和上一讲手写的例子几乎一样，只是多加了雾效（Fog）支持。它是最适合入门"顶点/片元着色器"的模板。

```hlsl
Shader "Unlit/NewUnlitShader"
{
    Properties
    {
        _MainTex ("Texture", 2D) = "white" {}
    }
    SubShader
    {
        Tags { "RenderType"="Opaque" }
        LOD 100

        Pass
        {
            CGPROGRAM
            #pragma vertex vert
            #pragma fragment frag
            #pragma multi_compile_fog

            #include "UnityCG.cginc"

            struct appdata
            {
                float4 vertex : POSITION;
                float2 uv : TEXCOORD0;
            };

            struct v2f
            {
                float2 uv : TEXCOORD0;
                UNITY_FOG_COORDS(1)
                float4 vertex : SV_POSITION;
            };

            sampler2D _MainTex;
            float4 _MainTex_ST;

            v2f vert (appdata v)
            {
                v2f o;
                o.vertex = UnityObjectToClipPos(v.vertex);
                o.uv = TRANSFORM_TEX(v.uv, _MainTex);
                UNITY_TRANSFER_FOG(o, o.vertex);
                return o;
            }

            fixed4 frag (v2f i) : SV_Target
            {
                fixed4 col = tex2D(_MainTex, i.uv);
                UNITY_APPLY_FOG(i.fogCoord, col);
                return col;
            }
            ENDCG
        }
    }
}
```text

相比上一讲，新增的是雾效三件套：

- `#pragma multi_compile_fog`：编译出"有雾/无雾"两个变体。
- `UNITY_FOG_COORDS(1)`：在 `v2f` 里声明雾坐标，参数 `1` 表示占用 TEXCOORD1 插值器。
- `UNITY_TRANSFER_FOG(o, o.vertex)`（vert 里）和 `UNITY_APPLY_FOG(i.fogCoord, col)`（frag 里）：传递并应用雾效。

这三行是"标准套路"，做自定义 Unlit 时保留它们，就能自动兼容场景雾。

## 四、Image Effect Shader：屏幕后处理的入口

### 4.1 生成代码

```hlsl
Shader "Hidden/NewImageEffectShader"
{
    Properties
    {
        _MainTex ("Texture", 2D) = "white" {}
    }
    SubShader
    {
        Cull Off ZWrite Off ZTest Always

        Pass
        {
            CGPROGRAM
            #pragma vertex vert
            #pragma fragment frag

            #include "UnityCG.cginc"

            struct appdata
            {
                float4 vertex : POSITION;
                float2 uv : TEXCOORD0;
            };

            struct v2f
            {
                float2 uv : TEXCOORD0;
                float4 vertex : SV_POSITION;
            };

            v2f vert (appdata v)
            {
                v2f o;
                o.vertex = UnityObjectToClipPos(v.vertex);
                o.uv = v.uv;
                return o;
            }

            sampler2D _MainTex;

            fixed4 frag (v2f i) : SV_Target
            {
                fixed4 col = tex2D(_MainTex, i.uv);
                return col;
            }
            ENDCG
        }
    }
}
```text

### 4.2 它和 Unlit 的区别

关键就在这一行状态：

```hlsl
Cull Off ZWrite Off ZTest Always
```text

屏幕后处理不画"3D 物体"，而是画一张**铺满屏幕的四边形（Quad）**，因此：

- `Cull Off`：不剔除任何面（否则转到背面就看不见了）。
- `ZWrite Off`：不写深度（它本身就是最终画面，不该遮挡其他东西）。
- `ZTest Always`：总是通过深度测试（无视之前画了什么）。

`_MainTex` 在这里不是美术贴图，而是**渲染管线传进来的上一帧画面**。在 Built-in 下，配一个 C# 脚本的 `OnRenderImage` 就能跑起来：

```csharp
void OnRenderImage(RenderTexture src, RenderTexture dst)
{
    Graphics.Blit(src, dst, material); // 用 material 处理 src 并写到 dst
}
```text

### 4.3 命名空间 Hidden

模板的 Shader 名是 `"Hidden/NewImageEffectShader"`。`Hidden/` 前缀会让它**不出现在普通材质下拉菜单里**（只在代码里被引用），这是后处理 Shader 的惯例，避免美术误用。

## 五、Compute Shader：GPU 通用计算

### 5.1 生成代码

Compute Shader 不是 `.shader` 而是 `.compute` 文件，生成内容如下：

```hlsl
#pragma kernel CSMain

RWTexture2D<float4> Result;

[numthreads(8,8,1)]
void CSMain (uint3 id : SV_DispatchThreadID)
{
    Result[id.xy] = float4(id.x / 8.0, id.y / 8.0, 0.0, 1.0);
}
```text

### 5.2 逐行解析

- `#pragma kernel CSMain`：声明一个计算入口（kernel）叫 `CSMain`。一个文件可以有多个 kernel。
- `RWTexture2D<float4> Result`：一块可读写的 2D 纹理，用来存结果。
- `[numthreads(8,8,1)]`：定义线程组大小——每组 8×8×1 个线程。
- `SV_DispatchThreadID`：当前线程在整个调度里的全局编号，用它定位"我这个线程算哪个像素"。
- 函数体：把像素坐标换算成颜色写进 `Result`。

### 5.3 它和普通 Shader 的区别

Compute Shader **不参与渲染流水线**，没有 vert/frag，也没有自动的光栅化。它是"用 GPU 做并行算术"，由 C# 显式调度：

```csharp
computeShader.SetTexture(0, "Result", renderTexture);
computeShader.Dispatch(0, width / 8, height / 8, 1);
```text

适合海量并行的场景：GPU 粒子、网格生成、流体模拟、图像处理。它是 Shader 家族里"最像通用程序"的一员。

## 六、模板适用场景对照

| 需求 | 推荐模板 |
| :--- | :--- |
| 普通 PBR 材质、快速出效果 | Standard Surface Shader |
| 无光照纯色/贴图、自定义特效 | Unlit Shader |
| 全屏滤镜、后处理 | Image Effect Shader |
| 大规模并行计算 | Compute Shader |
| 可视化连线、不写代码 | Shader Graph（下一讲） |
