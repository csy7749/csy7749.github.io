Unity Shader（1）：渲染管线总览

Created2026-08-13|Updated2026-08-18|UnityShader
|Post Views:

Shader 本质上是一段跑在 GPU 上的小程序。想真正看懂它，先得搞明白”一个三角形是怎么变成屏幕上的像素的”。本文从 GPU 渲染流水线讲起，再解释 Unity 的三种渲染管线（Built-in / URP / HDRP）以及它们背后的 SRP 机制，最后说清 Shader 与 Material 的分工。全文不写复杂语法，只为给你一张可随时回看的”全局地图”。

一、从三角形到像素：GPU 渲染流水线

你屏幕上的每一帧画面，都经历了”几何数据 → 像素颜色”的转换。这个过程被拆成若干阶段，统称为渲染流水线（Rendering Pipeline）。不同版本的图形 API（OpenGL / Direct3D / Vulkan / Metal）细节略有差异，但大框架一致。

1.1 应用阶段：一切从 CPU 开始

CPU 把场景里的物体一个个整理好——顶点位置、法线、UV、贴图、材质参数——然后通过图形 API 发出 Draw Call，告诉 GPU”画这个物体”。

这个阶段的关键词是 Draw Call。它很贵，因为它是一次”CPU 给 GPU 下指令”的完整往返。以后讲性能优化时，你会反复听到”减少 Draw Call”。

1.2 几何阶段：顶点在这里被变换

  • 顶点着色器（Vertex Shader）：每个顶点执行一次。最核心的工作是把顶点从模型空间变换到裁剪空间（这一般是 UnityObjectToClipPos 宏干的事），同时可以顺手处理颜色、UV 等数据。
  • 曲面细分 / 几何着色器：都是可选项。前者能程序化地增加顶点密度，后者能基于图元生成新图元。Unity 手写 Shader 里用得不多，知道即可。
  • 裁剪与屏幕映射：把视野之外、或位于相机背后的几何体裁掉，再把剩余部分映射到屏幕的二维坐标。

1.3 光栅化阶段：从三角形到片元

  • 光栅化（Rasterization）：决定一个三角形覆盖了屏幕上的哪些像素，并为每个被覆盖的像素生成一个 片元（Fragment）。
  • 片元着色器（Fragment Shader）：每个片元执行一次，计算它的最终颜色。这是 Shader 效果（光照、贴图、混合）的主战场。
  • 逐片元操作：在颜色写入帧缓冲前，做深度测试、模板测试、颜色混合等。这些”开关”（ZWrite、ZTest、Blend）在第 8 讲会专门展开。

一句话记忆：顶点着色器管”点”，片元着色器管”像素”。一个三角形的顶点只有 3 个，但它覆盖的像素可能有成千上万个，所以片元着色器通常比顶点着色器贵得多。

二、Shader 在流水线里扮演什么角色

Shader 不是一个整体程序，而是流水线上若干可编程阶段各自的小程序。Unity 里最常用的两个入口：

  • 顶点着色器（vert）：输入一个顶点的属性，输出变换后的位置和其他需要传给片元的量。
  • 片元着色器（frag）：输入顶点着色器输出的插值结果，输出该像素的颜色。

三、Unity 的三种渲染管线

“渲染管线”这个词在 Unity 里有两层含义：上面讲的是图形学层面的流水线；下面要讲的是 Unity 层面的管线——它决定 Unity 用哪套规则来组织渲染、光照、后处理，以及你的 Shader 该引用哪些头文件和宏。

3.1 Built-in Render Pipeline（内置管线）

Unity 最老、默认存在的那套管线。它把可编程部分（你可以写 Shader）和固定功能（光照、阴影、后处理等内置逻辑）混在一起。

  • 优点：资料多、旧项目都在用、Surface Shader 方便、无需额外配置。
  • 缺点：内部逻辑黑盒、难以深度定制、性能优化手段有限；新特性（如更好的渲染特性、通用渲染能力）逐渐不再优先支持。

3.2 Universal Render Pipeline（URP，通用渲染管线）

面向移动端和中低端设备的可编程管线，是目前 Unity 主推的默认选择。

  • 优点：基于 SRP 可定制、性能好（SRP Batcher、单 Pass 前向渲染等）、跨平台一致、Shader Graph 完整支持。
  • 缺点：写法与 Built-in 不同（头文件、宏变了），旧教程代码不能直接照搬。

3.3 High Definition Render Pipeline（HDRP，高清渲染管线）

面向高端 PC / 主机的物理精确管线。

  • 优点：光照物理正确、体积光、高质量后处理、真实感强。
  • 缺点：性能开销大、学习曲线陡、不适合移动端。

本文系列以 URP 为主、Built-in 为辅：用 Built-in 讲清楚 ShaderLab 本质（结构最简单直观），用 URP 讲现代写法和可落地实战。

四、SRP：可编程渲染管线到底是什么

URP 和 HDRP 都建立在 Scriptable Render Pipeline（SRP） 之上。SRP 的核心思想是：把”渲染流程”从引擎内部的黑盒，变成你可以在 C# 里改写的代码。

  • 在 Built-in 里，渲染顺序、Pass 调度、光照计算大多由 Unity 内部固定逻辑决定。
  • 在 SRP 里，你可以写一个继承自 RenderPipelineAsset / RenderPipeline 的 C# 类，自己决定”什么时候画什么、用什么 Pass、做不做后处理”。

URP 和 HDRP 就是 Unity 官方基于 SRP 提供的两套”开箱即用”的实现，所以它们也被称为 URP 管线和 HDRP 管线。

SRP 对 Shader 的影响（这是关键）：

  • 不同 SRP 提供的宏和头文件不同，同一个 UnityCG.cginc 在 URP 下不可用，要换成 URP 自己的头文件。
  • 顶点变换、光照计算等常用宏，在不同管线里封装的名字和参数可能不一样。

这就是为什么”照着旧教程抄 Built-in Shader 到 URP 项目里报错”——不是代码错了，是管线换了。

五、Shader 与 Material：程序与数据的分工

这是初学者最容易混的一对概念：

  • Shader（着色器）：一段程序，定义了”怎么算颜色”的逻辑。它不含具体数值。
  • Material（材质）：Shader 的一个实例，保存了所有具体参数（颜色、贴图、数值）。你可以把同一个 Shader 配出无数个材质。

打个比方：Shader 是”菜谱”，Material 是”按菜谱做好的一盘菜”。菜谱定义步骤，菜里是具体的食材分量。改 Material 不改 Shader；改 Shader 会影响所有用它的 Material。

六、一个 Shader 从上屏的完整路径

把上面所有概念串成一条线：

  1. 编写：你在编辑器里写 .shader 文件（ShaderLab + HLSL）。
  2. 导入编译：Unity 导入时会解析 ShaderLab，把它转成目标平台能用的 GPU 程序；其中不同 keyword 组合会编译成多个变体。
  3. 引用：创建一个 Material，选择这个 Shader，填好参数，挂到物体上。
  4. 渲染：运行时，Renderer 提交这个物体，Unity 按其管线决定调用哪些 Pass。
  5. 执行：GPU 依次跑顶点着色器、光栅化、片元着色器，把结果写进帧缓冲。
  6. 上屏：帧缓冲经交换链送到显示器。

第 11 讲会回到这条路径，讲变体是怎么膨胀包体的，以及怎么用 Frame Debugger 把它拆开看。

七、自查清单

  • 能说出 GPU 流水线从顶点到片元的主要阶段
  • 能解释”顶点着色器逐顶点、片元着色器逐片元”的含义
  • 能区分图形学层面的”渲染流水线”和 Unity 层面的”渲染管线”
  • 能说清 Built-in / URP / HDRP 三者的目标平台与适用场景
  • 知道 SRP 是什么，以及它为什么会导致 Shader 写法不通用
  • 能区分 Shader（逻辑）与 Material（数据）
