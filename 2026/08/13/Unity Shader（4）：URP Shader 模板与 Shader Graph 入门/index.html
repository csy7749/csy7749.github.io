Unity Shader（4）：URP Shader 模板与 Shader Graph 入门

Created2026-08-13|Updated2026-08-18|UnityShader
|Post Views:

上一讲拆的是 Built-in 的模板，这一讲切到 URP。URP 是当前新项目的默认管线，它的 Shader 写法和 Built-in 有本质区别：头文件变了、纹理采样变了、还多了为 SRP Batcher 服务的数据声明。本文先讲 URP 自带的几个 Shader 模板，再逐行解析 URP Unlit 模板，最后带你看 Shader Graph 的入门逻辑，以及”手写 HLSL vs 连线”该怎么选。

一、URP 的 Shader 模板清单

URP 项目里 Create → Shader 会多出一组 URP 模板，常见的有：

模板 作用
Lit Shader 完整 PBR 光照，URP 的主力材质模板
Simple Lit Shader 轻量 PBR，省性能，移动端常用
Baked Lit Shader 仅烘焙光照，最省，适合静态场景
Unlit Shader 无光照，最纯粹的 vert/frag 骨架

另外还有 Create → Shader Graph 下的可视化模板（见本文第四节）。

关键前提：这些 URP Shader 必须在启用了 URP 管线资源的项目里才正常。它们都带有一个 RenderPipeline 标签，告诉 Unity”我是 URP 的 Shader”。

二、URP 与 Built-in 写法的核心差异

先看一张对照表，再逐行看代码会更轻松：

事项 Built-in URP
代码块 CGPROGRAM ... ENDCG HLSLPROGRAM ... ENDHLSL
核心头文件 UnityCG.cginc Core.hlsl 等 URP 头文件
顶点变换宏 UnityObjectToClipPos TransformObjectToHClip
纹理采样 tex2D(_Tex, uv) SAMPLE_TEXTURE2D(_Tex, sampler_Tex, uv)
纹理声明 sampler2D _Tex TEXTURE2D(_Tex); SAMPLER(sampler_Tex);
常量缓冲 隐式 CBUFFER_START/END（SRP Batcher 要求）
管线标签 无 "RenderPipeline"="UniversalPipeline"
LightMode 无强制 "LightMode"="UniversalForward" 等

这 7 个差异，就是”旧教程代码搬到 URP 报错”的全部原因。

3.1 管线标签

"RenderPipeline"="UniversalPipeline" 是 URP Shader 的身份证。没有它，Shader 可能被当作 Built-in 处理，出现各种资源错误。

3.2 头文件与代码块

URP 下改用 HLSLPROGRAM/ENDHLSL，核心头文件是包内的 Core.hlsl，里面定义了 TransformObjectToHClip、TRANSFORM_TEX 等宏。光照相关则要再引入 Lighting.hlsl 等（第 6 讲会用到）。

3.3 CBUFFER：为 SRP Batcher 服务

把每个材质都可能不同的参数放进常量缓冲 UnityPerMaterial，是 SRP Batcher 能批量处理的关键前提之一。写法上它替代了 Built-in 里”裸声明变量”的方式。规则很简单：材质级参数放 CBUFFER 里，全局/引擎级参数放外面。

3.4 纹理声明与采样宏

不再写 sampler2D _BaseMap;。URP 用 TEXTURE2D / SAMPLER 宏声明纹理和采样器，配合统一的采样宏：

这套宏背后兼容了多平台和纹理数组，是现代 URP 的推荐写法。

3.5 命名约定：positionOS / positionHCS

  • Attributes（顶点输入）里 positionOS 的 OS = Object Space（模型空间）。
  • Varyings（顶点输出）里 positionHCS 的 HCS = Homogeneous Clip Space（齐次裁剪空间）。

TransformObjectToHClip 就对应 Built-in 的 UnityObjectToClipPos，把模型空间变换到裁剪空间。

四、Shader Graph 入门

Shader Graph 是 Unity 的可视化 Shader 编辑器：用节点连线替代写代码，适合不熟悉 HLSL 的同事或快速出效果。

4.1 常见 Shader Graph 模板

Create → Shader Graph → URP 下有：

模板 用途
Lit Shader Graph 完整 PBR 的连线起点
Unlit Shader Graph 无光照的连线起点
Sprite Lit / Unlit 2D 精灵
Full Screen Shader Graph 全屏后处理（配合 Renderer Feature）

4.2 三个核心概念

  • 属性（Blackboard）：相当于 Properties，定义颜色、贴图、数值参数，右侧面板可调。
  • 节点（Node）：一个节点就是一段计算，如 Sample Texture 2D、Add、Multiply、Lerp。
  • 输出（Main Preview / Output）：连线最终汇入一个输出节点（Lit 或 Unlit），对应”最终颜色/表面属性”。

一个最简单的 Unlit Shader Graph 是：Sample Texture 2D 的输出 → 乘 Color → 接 Base Color → 输出。它背后生成的 HLSL 和上面手写的 URP Unlit 本质相同。

4.3 手写 HLSL vs Shader Graph 怎么选

场景 推荐
纯逻辑特效、需要精确控制 Pass/变体 手写 HLSL
团队里有人不写代码、想快速出材质 Shader Graph
做复杂光照、后处理 手写 HLSL（配合 Renderer Feature）
原型验证、贴图混合、简单溶解 Shader Graph

两者并不互斥：Shader Graph 支持自定义函数节点（Custom Function Node），可以在连线里嵌入手写 HLSL。

五、自查清单

  • 能说出 URP 与 Built-in 在头文件、代码块、采样、变换宏上的差异
  • 知道 "RenderPipeline"="UniversalPipeline" 标签的作用
  • 知道 CBUFFER_START(UnityPerMaterial) 是为了什么
  • 能看懂 TEXTURE2D / SAMPLER / SAMPLE_TEXTURE2D 三件套
  • 能解释 positionOS 与 positionHCS 的命名含义
  • 知道 URP Lit 模板由多个带 LightMode 的 Pass 组成
  • 能说清 Shader Graph 的”属性/节点/输出”三者关系，以及它与手写 HLSL 的选择依据
