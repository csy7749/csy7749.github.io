Lua（10）：Lua C API 与宿主嵌入

Created2026-08-19|Updated2026-08-19|编程语言Lua
|Post Views:

前 9 篇都在 Lua 世界里打转，这一篇跨出边界：怎么用 C 把一个 Lua 解释器嵌进自己的程序。理解 C API 的”栈模型”，你才能真正看懂 xLua/ToLua 的生成代码在干什么，也才能为引擎、工具链、服务器写自己的脚本层。

一、为什么需要自己嵌 Lua

Lua 的典型宿主有四种：

  • 游戏引擎：脚本层调用引擎能力（xLua/ToLua 就是这个模型的 C# 版）；
  • 服务器/网关：OpenResty、Redis 用 C 内嵌 Lua 做可编程逻辑；
  • 编辑器/工具链：用 Lua 做宏、做自动化；
  • 独立 CLI：把 Lua 当配置+扩展语言嵌进自己的程序。

无论哪种，骨架都是同一个：创建解释器 → 打开库 → 跑脚本 → 释放。

生命周期要点：一个 lua_State 就是一个隔离的解释器（独立全局环境、独立 GC）。服务器做多租户/沙箱时，每个租户一个 lua_State 比手动清环境干净得多。

三、栈模型：一切交互都是压栈/弹栈

Lua 与 C 之间没有”直接传参”，只有一条虚拟栈：要传值就 push，要取值就按索引读，用完记得 pop。

栈纪律是 C API 的第一铁律：

  • 谁 push 谁负责 pop，函数退出前栈要”原样归还”（除了你要返回的结果）；
  • 用 lua_gettop(L) 记录基准，用 lua_settop(L, 基准) 一键回滚；
  • luaL_check* 系列（luaL_checkinteger 等）会在类型不对时直接抛错，别手写一堆 if。

四、C 调用 Lua 函数

lua_pcall 失败时栈顶是错误对象（通常是字符串），lua_tostring 可读。注意 lua_Integer 在 5.3+ 是 64 位，lua_tointeger 返回值类型要对应，别用 int 接。

六、userdata：把 C 对象安全暴露给 Lua

跨语言传”指针”不能直接传数字（会被 Lua 代码伪造），正确姿势是完整 userdata：分配一块 C 结构体内存给 Lua 管，再用元表做类型检查与方法。

要点：

  • luaL_checkudata(L, 1, "Vec2") 会校验 userdata 的元表名，类型错就抛错——这比”裸指针当整数传”安全一个量级；
  • 5.4 里带 __gc 的 userdata 被回收时会回调，资源类对象（文件、纹理句柄）记得在 __gc 里释放；
  • 轻量 userdata（light userdata）是”裸地址”且无元表，只适合做”身份标记”，别存需要析构的资源。

七、错误处理：luaL_error 与错误码

  • C 函数里用 luaL_error(L, "message") 抛错，错误会沿调用链被 pcall/lua_pcall 接住；
  • 宿主侧所有”调 Lua”的入口都要包 lua_pcall 并处理非零返回值；
  • C 与 Lua 的错误边界：C 侧的崩溃（段错误）救不回来，所以 luaL_check* 这类”先验证再干活”的 API 要勤用，别信”反正 Lua 传啥都行”。

自查清单

  • 能写出最小宿主（newstate → openlibs → dofile → close）
  • 理解栈模型，遵守”谁 push 谁 pop”的栈纪律
  • 会用 lua_pcall 调 Lua 函数并读取结果
  • 会注册 C 函数，并理解 return n 的意义
  • 会用 userdata + 元表暴露 C 对象，并挂 __gc
