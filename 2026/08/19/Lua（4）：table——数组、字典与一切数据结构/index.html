Lua（4）：table——数组、字典与一切数据结构

Created2026-08-19|Updated2026-08-19|编程语言Lua
|Post Views:

table 是 Lua 唯一的复合数据结构，也是它”数组、字典、对象、集合”全包的原因。理解它”数组部分 + 哈希部分”的内部布局，才能避开 # 运算符和遍历顺序上的那些坑。这篇把 table 的创建、索引、遍历、常用操作和性能要点一次讲清。

二、内部布局：数组部分 + 哈希部分

Lua 的实现里，一个 table 通常由两部分构成：

  • 数组部分：从 1 开始的连续整数键，紧凑存储，访问 O(1)；
  • 哈希部分：其余所有键（字符串、非 1 起始的整数、其他类型），走哈希表。

这一设计决定了三条规则：

  1. ipairs 只遍历数组部分，”见到 nil 就停”；
  2. pairs 遍历全部键，但哈希部分顺序不保证；
  3. # 只对数组部分有意义，遇到空洞行为未定义。

四、遍历：ipairs / pairs / next

  • 只遍历数组用 ipairs；要遍历全部键用 pairs。
  • 遍历过程中不要新增/删除键（修改已有键的值可以）；要边遍历边增删，先收集到临时表再处理。

七、性能提示

  • 尽量只在数组末尾操作：table.insert(list, i, v) 与 table.remove(list, i) 在中间是 O(n) 搬运，频繁往头部插队会拖慢热路径。
  • 字符串拼接走 table.concat：a = a .. b 每次新建字符串，循环里是 O(n²)；先收集到表再 concat 是 O(n)。
  • LuaJIT 可预分配容量（PUC Lua 没有）：local t = require("table.new")(16, 8) 预先给数组 16、哈希 8 的容量，减少 rehash。
  • 复用表比新建表省 GC：高频调用里用一个局部临时表反复清空填充，好过每次 local t = {}（详见第 9 讲）。

自查清单

  • 能说清数组部分与哈希部分的差别，解释 pairs/ipairs 顺序
  • 知道 # 对空洞表不可靠，会用 next(t) == nil 判空
  • 会用 insert / remove / concat / sort，并知道 sort 不稳定
  • 能用手写栈、队列、集合，并知道中间 remove 的代价
