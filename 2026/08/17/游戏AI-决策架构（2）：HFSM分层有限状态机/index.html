游戏AI-决策架构（2）：HFSM 分层有限状态机

Created2026-08-17|Updated2026-08-17|游戏AI决策架构
|Post Views:

HFSM（Hierarchical Finite State Machine，分层有限状态机）在 FSM 之上增加父子层级，让一组相关状态共享生命周期、更新逻辑和迁移规则。它解决的不是“如何让状态更多”，而是“如何把重复关系提升到共同父状态，同时保留明确的执行边界”。

本文假设已经理解 FSM 的状态、迁移和 Enter / Update / Exit。示例使用 .NET 8 与 C#，重点实现 HFSM 最容易出错的部分：激活路径、父层迁移，以及跨层切换时的退出和进入顺序。

一、为什么平铺 FSM 会出现重复

守卫 NPC 有三个战斗相关状态：

  • Chase：追击目标
  • Attack：攻击目标
  • Search：短暂搜索丢失的目标

它们通常共享一组规则：进入战斗时锁定目标、持续刷新威胁、离开战斗时清理目标；低血量时都要撤退，目标彻底丢失时都要回到巡逻。

平铺 FSM 只能把这些规则复制到每个状态：

Chase  --低血量--> Flee
Attack --低血量--> Flee
Search --低血量--> Flee

Chase  --目标丢失--> Patrol
Attack --目标丢失--> Patrol
Search --目标丢失--> Patrol
```text

增加一个 `TakeCover` 状态后，还要再补两条迁移。HFSM 把共同关系提升到 `Combat`：

```text
Root
├── Peace
│   └── Patrol
├── Combat
│   ├── Chase
│   └── Attack
└── Flee

Combat --目标丢失--> Patrol
Root   --低血量----> Flee
```text

这样 `Combat` 不是一个只用来分组的文件夹，而是一个真正的父状态：它有进入、更新、退出行为，也能声明对子状态共同生效的迁移。这种层级状态思想来自 Harel 对 Statecharts 的形式化扩展：用层级、并发和通信缓解传统状态图的状态爆炸问题[^1]。

## 二、当前状态变成一条激活路径

普通 FSM 的当前状态是一个值：

```text
Current = Attack
```text

HFSM 的当前配置是一条从根到叶子的路径：

```text
ActivePath = Root -> Combat -> Attack
```text

一次 Tick 通常会让激活路径上的状态按父到子顺序更新：

```text
Root.Update()
Combat.Update()
Attack.Update()
```text

父状态适合处理共享上下文，叶状态负责具体动作。若父状态直接操纵攻击动画、叶状态又控制同一动画，两层就会争夺执行权；分层只消除真正共同的职责，不应该把所有逻辑都向父层搬。

## 三、跨层迁移的核心：最近公共祖先

假设当前路径为：

```text
Root -> Combat -> Attack
```text

目标路径为：

```text
Root -> Peace -> Patrol
```text

两条路径的最近公共祖先是 `Root`。正确切换顺序是：

```text
Exit Attack
Exit Combat
Enter Peace
Enter Patrol
```text

这里的 `Root` 没有离开再进入，因为它仍然处于激活路径上。若从 `Attack` 切到同父级的 `Chase`，最近公共祖先变成 `Combat`，只需要：

```text
Exit Attack
Enter Chase
```text

这套算法让跨层迁移不必硬编码“退出几层、进入几层”。只要父子关系正确，状态机就能统一计算生命周期路径。

《Game Programming Patterns》也把分层状态机作为减少状态行为重复的直接扩展：子状态处理差异，父状态保留共同实现[^2]。

## 四、一个可运行的 HFSM

下面的实现用叶状态保存当前执行位置。迁移的源可以是任意祖先：`Combat -> Patrol` 会同时作用于 `Chase` 和 `Attack`，`Root -> Flee` 则是全局迁移。

```csharp
using System;
using System.Collections.Generic;
using System.Linq;

public sealed record GuardContext(
    bool EnemyVisible,
    float DistanceToEnemy,
    bool LowHealth);

public class HState
{
    public string Name { get; }
    public HState? Parent { get; }

    public HState(string name, HState? parent = null)
    {
        Name = name;
        Parent = parent;
    }

    public virtual void Enter() => Console.WriteLine($"Enter {Name}");

    public virtual void Update(GuardContext context)
    {
        Console.WriteLine($"Update {Name}");
    }

    public virtual void Exit() => Console.WriteLine($"Exit {Name}");

    public bool Contains(HState state)
    {
        for (var cursor = state; cursor is not null; cursor = cursor.Parent)
        {
            if (ReferenceEquals(cursor, this))
            {
                return true;
            }
        }

        return false;
    }
}

public sealed record HTransition(
    HState Source,
    HState Target,
    Func<GuardContext, bool> Condition)
{
    public bool Applies(HState activeLeaf, GuardContext context)
    {
        return Source.Contains(activeLeaf) && Condition(context);
    }
}

public sealed class HierarchicalStateMachine
{
    private readonly HState _root;
    private readonly IReadOnlyList<HTransition> _transitions;
    private HState _activeLeaf;

    public HierarchicalStateMachine(
        HState root,
        HState initialLeaf,
        IReadOnlyList<HTransition> transitions)
    {
        _root = root;
        _activeLeaf = initialLeaf;
        _transitions = transitions;
        EnterInitialPath();
    }

    public void Tick(GuardContext context)
    {
        var transition = _transitions.FirstOrDefault(
            item => item.Applies(_activeLeaf, context));

        if (transition is not null && !ReferenceEquals(transition.Target, _activeLeaf))
        {
            ChangeState(transition.Target);
        }

        foreach (var state in GetPath(_activeLeaf))
        {
            state.Update(context);
        }
    }

    private void ChangeState(HState target)
    {
        var ancestor = FindCommonAncestor(_activeLeaf, target);
        Console.WriteLine($"Transition: {_activeLeaf.Name} -> {target.Name}");
        ExitToAncestor(_activeLeaf, ancestor);
        EnterFromAncestor(target, ancestor);
        _activeLeaf = target;
    }

    private void EnterInitialPath()
    {
        if (!_root.Contains(_activeLeaf))
        {
            throw new InvalidOperationException("Initial state is outside the root tree.");
        }

        foreach (var state in GetPath(_activeLeaf))
        {
            state.Enter();
        }
    }

    private static void ExitToAncestor(HState state, HState ancestor)
    {
        for (var cursor = state; !ReferenceEquals(cursor, ancestor); cursor = cursor.Parent!)
        {
            cursor.Exit();
        }
    }

    private static void EnterFromAncestor(HState target, HState ancestor)
    {
        var pending = new Stack<HState>();
        for (var cursor = target; !ReferenceEquals(cursor, ancestor); cursor = cursor.Parent!)
        {
            pending.Push(cursor);
        }

        while (pending.Count > 0)
        {
            pending.Pop().Enter();
        }
    }

    private static HState FindCommonAncestor(HState source, HState target)
    {
        var sourcePath = new HashSet<HState>();
        for (var cursor = source; cursor is not null; cursor = cursor.Parent)
        {
            sourcePath.Add(cursor);
        }

        for (var cursor = target; cursor is not null; cursor = cursor.Parent)
        {
            if (sourcePath.Contains(cursor))
            {
                return cursor;
            }
        }

        throw new InvalidOperationException("States do not share a root.");
    }

    private static IReadOnlyList<HState> GetPath(HState leaf)
    {
        var path = new List<HState>();
        for (var cursor = leaf; cursor is not null; cursor = cursor.Parent)
        {
            path.Add(cursor);
        }

        path.Reverse();
        return path;
    }
}

public static class Program
{
    private const float AttackRange = 2.0f;

    public static void Main()
    {
        var root = new HState("Root");
        var peace = new HState("Peace", root);
        var patrol = new HState("Patrol", peace);
        var combat = new HState("Combat", root);
        var chase = new HState("Chase", combat);
        var attack = new HState("Attack", combat);
        var flee = new HState("Flee", root);

        var transitions = new List<HTransition>
        {
            new(root, flee, context => context.LowHealth),
            new(flee, patrol, context => !context.LowHealth),
            new(patrol, chase, context => context.EnemyVisible),
            new(combat, patrol, context => !context.EnemyVisible),
            new(chase, attack, IsInAttackRange),
            new(attack, chase, IsOutsideAttackRange)
        };

        var machine = new HierarchicalStateMachine(root, patrol, transitions);
        machine.Tick(new GuardContext(true, 8.0f, false));
        machine.Tick(new GuardContext(true, 1.5f, false));
        machine.Tick(new GuardContext(false, 10.0f, false));
        machine.Tick(new GuardContext(false, 10.0f, true));
    }

    private static bool IsInAttackRange(GuardContext context)
    {
        return context.EnemyVisible && context.DistanceToEnemy <= AttackRange;
    }

    private static bool IsOutsideAttackRange(GuardContext context)
    {
        return !context.EnemyVisible || context.DistanceToEnemy > AttackRange;
    }
}
```text

这段代码刻意完整实现进入和退出路径，没有用“直接把当前叶状态改成目标状态”的简化写法。后者看似能跑，却会漏掉父状态的清理和初始化，是 HFSM 中最隐蔽的一类错误。

## 五、父层和子层迁移如何竞争

当前处于 `Root -> Combat -> Attack` 时，下面两条迁移可能同时成立：

```text
Root   --低血量--> Flee
Attack --距离过远--> Chase
```text

必须定义优先级。常见策略有两种：

- **外层优先**：先检查根和父状态，适合死亡、眩晕、撤退等全局中断。
- **内层优先**：先检查叶状态，局部行为更容易覆盖父层默认规则。

示例使用有序迁移表，把全局撤退放在第一位。完整框架可以先按显式优先级排序，再按层级深度处理；重要的是同一组条件每次得到相同结果，并在日志中输出获胜迁移。

不要让父状态和子状态直接互相调用 `ChangeState`。所有迁移仍应经过同一个仲裁入口，否则层级优先级只是纸面规则。

## 六、默认子状态与历史状态

父状态本身通常不能作为最终执行位置。进入 `Combat` 时，需要决定进入哪个叶状态：

- **Initial State**：每次进入都从默认子状态开始，例如 `Combat -> Chase`。
- **Shallow History**：记住上次直接子状态。
- **Deep History**：记住上次完整子路径。

历史状态适合“被短暂打断后继续原流程”，例如攻击被硬直打断，恢复后回到攻击子阶段。但历史也会保存已经失效的上下文；目标死亡后仍恢复到 `Attack` 就不合理。因此恢复历史前仍要验证进入条件，失败时回到默认子状态。

示例直接把迁移目标写到叶状态，避开了默认/历史策略。真正封装框架时，应把它们作为显式配置，而不是在 `Enter` 里偷偷选择子状态。

UnityHFSM 等开源实现进一步提供了需要退出时间、全局迁移和嵌套状态机等工程能力，可用于对照自研框架的语义边界[^3]。

## 七、HFSM 不等于无限嵌套

HFSM 的层级越深，单个状态的行为来源越分散。调试 `Attack` 时可能同时受到 `Root`、`Alive`、`Combat`、`RangedCombat` 四层规则影响，理解成本并不会凭空消失。

适合升级 HFSM 的信号：

- 多个相邻状态共享同一组生命周期逻辑。
- 多个状态共享相同的高优先级迁移。
- 行为天然存在“模式 -> 子行为”的层级，例如地面/空中、和平/战斗。
- 需要在一个模式内切换子状态，同时保持父模式不退出。

不适合靠加层解决的问题：

- 移动和武器是两个可并行变化的维度，应考虑正交状态机。
- 高层目标需要多因素评分，应交给 Utility AI。
- 行为分支频繁按优先级重新评估，行为树往往更直接。
- 状态只是在转发服务调用，说明职责可能拆错了。

## 八、调试信息至少要包含什么

普通 FSM 输出 `Attack -> Flee` 还算清楚，HFSM 只输出叶状态就不够。至少记录：

- 切换前激活路径
- 命中的迁移来源层级
- 条件或事件名称
- 最近公共祖先
- 实际退出路径和进入路径
- 切换后的激活路径

例如：

```text
Before: Root/Combat/Attack
Rule: Root.LowHealth -> Flee
LCA: Root
Exit: Attack, Combat
Enter: Flee
After: Root/Flee
```text

有了这组信息，层级结构才真正可维护。

## 九、自查清单

- 当前执行位置是否用完整激活路径表达？
- 父状态是否承担真正共享的职责，而不只是目录分组？
- 跨层迁移是否通过最近公共祖先计算退出和进入路径？
- 父层与子层迁移冲突是否有确定优先级？
- 默认子状态、浅历史和深历史是否被显式区分？
- 日志能否还原命中的层级规则和完整生命周期路径？
- 层级过深时，是否应该改用行为树、正交状态机或高层决策器？
