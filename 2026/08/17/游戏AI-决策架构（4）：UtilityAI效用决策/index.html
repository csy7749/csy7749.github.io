游戏AI-决策架构（4）：Utility AI 效用决策

Created2026-08-17|Updated2026-08-17|游戏AI决策架构
|Post Views:

Utility AI（效用型 AI）把血量、距离、风险、资源等上下文转换成统一分数，再从候选行为中选择当前效用最高的一项。它解决的不是“动作如何执行”，而是多个因素同时变化时，角色此刻更应该攻击、治疗、撤退还是巡逻。

本文假设读者熟悉 C# 委托、集合和基本数学函数。示例使用 .NET 8，实现归一化输入、响应曲线、评分合成、惯性修正和可解释的候选输出，可以直接放进控制台项目运行。

一、Utility AI 解决什么问题

硬条件适合表达明确规则：

if 死亡 -> 进入死亡状态
if 技能未解锁 -> 禁止释放
```text

但下面这种选择很难只靠一组阈值维护：

```text
血量低，希望治疗或撤退
敌人很近，希望攻击或拉开距离
敌人很多，希望找掩体
治疗技能可用，但释放过程可能被打断
当前攻击已经进行一半，切换也有成本
```text

如果继续添加 `if / else`，不同条件的优先级会散落在代码顺序里，临界值附近还可能发生生硬切换。Utility AI 把问题改写为：

```text
Attack  = 0.65
Retreat = 0.56
Heal    = 0.52
Patrol  = 0.00

选择 Attack
```text

Utility Theory 的核心是把不同量纲的因素转换到统一效用尺度，再比较候选行为的相对吸引力。Game AI Pro 的 Utility Theory 章节建议保持评分尺度一致，常见做法是把输入和输出归一化到 `[0, 1]`[^1]。

## 二、核心模型

一个最小 Utility AI 通常包含五部分：

| 组件 | 职责 | 示例 |
| :--- | :--- | :--- |
| Context | 提供当前事实 | 血量、距离、敌人数、技能可用性 |
| Action / Option | 候选行为 | Attack、Heal、Retreat |
| Consideration | 评价候选的一个因素 | 当前血量是否支持继续攻击 |
| Response Curve | 把原始输入映射为效用 | 血量越低，治疗意愿越高 |
| Selector | 合成分数并选择候选 | 最高分、Top-N 或加权随机 |

决策和执行必须分开：

```text
Utility AI -> 选择 Heal
Executor   -> 检查技能、播放前摇、处理打断、报告完成
```text

如果评分器直接调用寻路、动画或技能，候选评估就会产生副作用。同一帧评分四个候选，可能意外启动四个动作。

## 三、先统一输入尺度

血量可能是 `0 ~ 5000`，距离可能是 `0 ~ 30` 米，敌人数量可能是 `0 ~ 20`。直接相加没有意义，因此先归一化：

```text
normalized = clamp((value - min) / (max - min), 0, 1)
```text

归一化之后仍然不能直接决定行为。`HealthRatio = 0.3` 只表示剩余 30% 血量，不表示治疗意愿一定是 0.7。这个映射由响应曲线负责。

系统边界上的输入需要明确处理：

- 最大值必须大于最小值，否则归一化公式无效。
- 外部输入超出范围时应记录数据错误，再根据明确规则裁剪。
- `NaN` 和无穷值不能进入评分系统，应直接暴露异常。
- 布尔条件可以映射为 0 或 1，用作硬门槛。

## 四、响应曲线表达“倾向”

同一个输入可以对应完全不同的行为意图。

### 线性曲线

```text
y = x
```text

输入增加多少，效用就增加多少。适合弹药充足度、目标可见度等关系明确的因素。

### 反向曲线

```text
y = 1 - x
```text

血量越低，撤退意愿越高。

### 幂曲线

```text
y = x^k
```text

当 `k > 1` 时，低输入阶段变化缓慢，接近高值后快速上升。反向后可以表达“血量进入危险区后，治疗意愿急剧增加”。

### S 曲线与分段曲线

S 曲线适合中间区间敏感、两端稳定的行为。分段曲线允许设计者直接指定关键点，例如血量高于 70% 时治疗分数为 0，低于 20% 后快速接近 1。Game AI Pro 以《The Sims》的饥饿需求为例说明了分段线性曲线的可调性[^1]。

曲线不是装饰。它定义了输入变化如何转化为行为倾向，往往也是 Utility AI 调试时间最多的地方。

## 五、多个 Consideration 怎么合成

一个攻击行为可能同时考虑：

- 当前血量是否安全
- 目标是否在理想距离
- 是否看见目标

常见合成方式有三种。

### 加权求和

```text
Score = sum(score_i * weight_i) / sum(weight_i)
```text

优点是直观；缺点是一个关键条件为 0 时，其他高分仍可能把总分抬起来。

### 直接相乘

```text
Score = score_1 * score_2 * ... * score_n
```text

任何关键项为 0，候选立即失效。但 Consideration 越多，乘积天然越小，不同候选的数量不一致时比较不公平。

### 几何平均

```text
Score = (score_1 * score_2 * ... * score_n) ^ (1 / n)
```text

它保留了“任一项为 0 就整体为 0”的门槛特性，同时减轻因子数量对分数尺度的影响。本文示例使用几何平均，便于解释和比较。

不存在通用的最佳公式。真正的要求是：合成规则固定、分数可回放、设计含义明确。

## 六、一个可运行的 Utility AI

下面的代码实现四个候选：攻击、撤退、治疗、巡逻。每个候选由多个 Consideration 组成，Selector 输出原始分数和加入惯性后的调整分数。

```csharp
#nullable enable

using System;
using System.Collections.Generic;
using System.Linq;

public sealed record DecisionContext
{
    public required double HealthRatio { get; init; }
    public required double EnemyDistance { get; init; }
    public required double EnemyCountRatio { get; init; }
    public required bool EnemyVisible { get; init; }
    public required bool HealAvailable { get; init; }
}

public interface IResponseCurve
{
    double Evaluate(double input);
}

public sealed class LinearCurve : IResponseCurve
{
    private readonly bool _inverted;

    public LinearCurve(bool inverted = false)
    {
        _inverted = inverted;
    }

    public double Evaluate(double input)
    {
        var normalized = Math.Clamp(input, 0.0, 1.0);
        return _inverted ? 1.0 - normalized : normalized;
    }
}

public sealed class PowerCurve : IResponseCurve
{
    private readonly double _exponent;
    private readonly bool _inverted;

    public PowerCurve(double exponent, bool inverted = false)
    {
        if (exponent <= 0.0)
        {
            throw new ArgumentOutOfRangeException(nameof(exponent));
        }

        _exponent = exponent;
        _inverted = inverted;
    }

    public double Evaluate(double input)
    {
        var normalized = Math.Clamp(input, 0.0, 1.0);
        var value = _inverted ? 1.0 - normalized : normalized;
        return Math.Pow(value, _exponent);
    }
}

public sealed class BandCurve : IResponseCurve
{
    private readonly double _center;
    private readonly double _halfWidth;

    public BandCurve(double center, double halfWidth)
    {
        if (halfWidth <= 0.0)
        {
            throw new ArgumentOutOfRangeException(nameof(halfWidth));
        }

        _center = center;
        _halfWidth = halfWidth;
    }

    public double Evaluate(double input)
    {
        var distance = Math.Abs(input - _center);
        return Math.Clamp(1.0 - distance / _halfWidth, 0.0, 1.0);
    }
}

public sealed record Consideration(
    string Name,
    Func<DecisionContext, double> Input,
    IResponseCurve Curve)
{
    public double Evaluate(DecisionContext context)
    {
        var value = Input(context);
        if (double.IsNaN(value) || double.IsInfinity(value))
        {
            throw new InvalidOperationException($"Invalid input for {Name}.");
        }

        return Curve.Evaluate(value);
    }
}

public sealed class UtilityOption
{
    public string Name { get; }
    private readonly IReadOnlyList<Consideration> _considerations;

    public UtilityOption(string name, IReadOnlyList<Consideration> considerations)
    {
        if (considerations.Count == 0)
        {
            throw new ArgumentException("At least one consideration is required.");
        }

        Name = name;
        _considerations = considerations;
    }

    public double Score(DecisionContext context)
    {
        var scores = _considerations.Select(item => item.Evaluate(context)).ToArray();
        if (scores.Any(score => score <= 0.0))
        {
            return 0.0;
        }

        var product = scores.Aggregate(1.0, (current, score) => current * score);
        return Math.Pow(product, 1.0 / scores.Length);
    }
}

public sealed record ScoredOption(
    string Name,
    double RawScore,
    double AdjustedScore);

public sealed record DecisionResult(
    string Selected,
    IReadOnlyList<ScoredOption> Scores);

public sealed class UtilitySelector
{
    private readonly IReadOnlyList<UtilityOption> _options;
    private readonly double _inertiaBonus;
    private string? _current;

    public UtilitySelector(IReadOnlyList<UtilityOption> options, double inertiaBonus)
    {
        if (options.Count == 0)
        {
            throw new ArgumentException("At least one option is required.");
        }

        _options = options;
        _inertiaBonus = inertiaBonus;
    }

    public DecisionResult Select(DecisionContext context)
    {
        var scores = _options.Select(option => ScoreOption(option, context)).ToArray();
        var selected = scores.OrderByDescending(item => item.AdjustedScore).First();
        _current = selected.Name;
        return new DecisionResult(selected.Name, scores);
    }

    private ScoredOption ScoreOption(UtilityOption option, DecisionContext context)
    {
        var raw = option.Score(context);
        var bonus = option.Name == _current ? _inertiaBonus : 0.0;
        return new ScoredOption(option.Name, raw, Math.Clamp(raw + bonus, 0.0, 1.0));
    }
}

public static class Program
{
    private const double MaxRelevantDistance = 10.0;
    private const double IdealAttackDistance = 0.2;
    private const double AttackDistanceTolerance = 0.25;
    private const double DangerExponent = 2.0;
    private const double HealExponent = 3.0;
    private const double InertiaBonus = 0.05;

    public static void Main()
    {
        var selector = new UtilitySelector(CreateOptions(), InertiaBonus);

        Evaluate(selector, new DecisionContext
        {
            HealthRatio = 0.35,
            EnemyDistance = 2.5,
            EnemyCountRatio = 0.75,
            EnemyVisible = true,
            HealAvailable = true
        });

        Evaluate(selector, new DecisionContext
        {
            HealthRatio = 0.18,
            EnemyDistance = 0.8,
            EnemyCountRatio = 1.0,
            EnemyVisible = true,
            HealAvailable = true
        });
    }

    private static IReadOnlyList<UtilityOption> CreateOptions()
    {
        return new[]
        {
            CreateAttack(),
            CreateRetreat(),
            CreateHeal(),
            CreatePatrol()
        };
    }

    private static UtilityOption CreateAttack()
    {
        return new UtilityOption("Attack", new Consideration[]
        {
            new("SafeHealth", context => context.HealthRatio, new LinearCurve()),
            new("IdealRange", NormalizeDistance, new BandCurve(
                IdealAttackDistance,
                AttackDistanceTolerance)),
            new("EnemyVisible", BoolEnemyVisible, new LinearCurve())
        });
    }

    private static UtilityOption CreateRetreat()
    {
        return new UtilityOption("Retreat", new Consideration[]
        {
            new("LowHealth", context => context.HealthRatio,
                new PowerCurve(DangerExponent, inverted: true)),
            new("EnemyPressure", context => context.EnemyCountRatio, new LinearCurve())
        });
    }

    private static UtilityOption CreateHeal()
    {
        return new UtilityOption("Heal", new Consideration[]
        {
            new("CriticalHealth", context => context.HealthRatio,
                new PowerCurve(HealExponent, inverted: true)),
            new("HealAvailable", BoolHealAvailable, new LinearCurve())
        });
    }

    private static UtilityOption CreatePatrol()
    {
        return new UtilityOption("Patrol", new Consideration[]
        {
            new("NoEnemy", BoolEnemyVisible, new LinearCurve(inverted: true))
        });
    }

    private static double NormalizeDistance(DecisionContext context)
    {
        return Math.Clamp(context.EnemyDistance / MaxRelevantDistance, 0.0, 1.0);
    }

    private static double BoolEnemyVisible(DecisionContext context)
    {
        return context.EnemyVisible ? 1.0 : 0.0;
    }

    private static double BoolHealAvailable(DecisionContext context)
    {
        return context.HealAvailable ? 1.0 : 0.0;
    }

    private static void Evaluate(UtilitySelector selector, DecisionContext context)
    {
        var result = selector.Select(context);
        Console.WriteLine($"Selected: {result.Selected}");

        foreach (var score in result.Scores)
        {
            Console.WriteLine(
                $"  {score.Name,-8} raw={score.RawScore:F3}, adjusted={score.AdjustedScore:F3}");
        }
    }
}
```text

输出结果如下：

```text
Selected: Attack
  Attack   raw=0.654, adjusted=0.654
  Retreat  raw=0.563, adjusted=0.563
  Heal     raw=0.524, adjusted=0.524
  Patrol   raw=0.000, adjusted=0.000
Selected: Retreat
  Attack   raw=0.454, adjusted=0.504
  Retreat  raw=0.820, adjusted=0.820
  Heal     raw=0.743, adjusted=0.743
  Patrol   raw=0.000, adjusted=0.000
```text

第二次评估时，`Attack` 因为是当前行为获得了 0.05 惯性加成，但危险已经足够高，`Retreat` 仍然获胜。惯性提高切换门槛，却不会把当前动作永久锁死。

## 七、为什么需要惯性和防震荡

如果两个候选分数接近，轻微输入变化就可能导致：

```text
Attack -> Retreat -> Attack -> Retreat
```text

GDC 的 Utility Theory 演讲讨论了响应曲线、加权随机和决策建模，用连续效用替代生硬的二元条件[^2]。工程中还需要显式处理时间维度。

### 惯性加成

给当前行为增加小幅分数，其他候选必须明显更好才能抢占。示例采用这种方式。

### 最短持续时间

动作开始后至少运行一段时间。适合不应频繁打断的动画或技能，但死亡、眩晕等硬中断必须绕过该限制。

### 切换成本

从攻击切换到撤退需要转身、取消技能和重新寻路，可以把这部分代价从新候选分数中扣除。

### 冷却

行为结束后暂时不参与选择，适合翻滚、特殊技能和语音等不应连续触发的动作。

### 降频评估

Utility AI 不必每帧评估所有候选。可以定时评估，或在血量、目标、技能可用性等关键输入变化时重新决策。

这些机制必须可配置、可记录。静默锁定当前行为只会把震荡变成“AI 为什么不切换”的另一种问题。

## 八、最高分不一定是唯一选择方式

示例采用确定性的最高分选择，便于测试和复现。其他常见策略包括：

- **Top-N 随机**：从分数最高的若干候选中随机。
- **阈值候选集**：选择与最高分差距不超过某个范围的候选。
- **按分数加权随机**：分数越高，被选中的概率越大。
- **分桶选择**：先选战斗、生活、紧急等类别，再在桶内评分。

纯加权随机可能偶尔选出明显不合理的低分行为。更稳妥的做法是先剔除不合格候选，再对高分集合做有限随机。Game AI Pro 同样比较了最高分、加权随机和高分子集选择的取舍[^1]。

## 九、评分系统的常见坑

### 用 0 分隐藏数据错误

导航系统没有初始化、目标引用失效不应该当成正常低效用。配置或数据错误需要抛出异常或明确记录。

### Consideration 数量失衡

直接相乘时，因子多的候选天然吃亏。应统一因子数量、使用补偿公式，或采用几何平均等明确规则。

### 曲线没有业务含义

随手拖出一条“看起来顺眼”的曲线，很难解释线上行为。每条曲线都应该能用一句话说明输入和期望倾向。

### 把硬约束也做成软分数

没有治疗技能时，`HealAvailable` 应直接让治疗候选变成 0，而不是给一个较低分后仍允许它偶尔获胜。

### 只记录最终选择

只看到“选择 Retreat”无法调参。必须同时记录原始输入、每个 Consideration 输出、候选合成分和惯性修正。

## 十、适用场景与边界

Utility AI 适合：

- 多个技能根据距离、血量、冷却和风险竞争。
- 攻击、治疗、撤退、找掩体之间持续权衡。
- 生活模拟中的需求与活动选择。
- RTS 中为任务挑选最适合的单位。
- 行为需要表现个性倾向，而不是固定条件链。

Utility AI 不擅长：

- 描述技能前摇、释放、后摇等严格流程。
- 自动生成多步动作计划。
- 管理复杂动作的中断与清理。
- 在没有调试工具时维护大量曲线和权重。

它经常位于执行器上方：

```text
Utility AI 选择 Retreat
        |
        v
行为树执行：寻找掩体 -> 移动 -> 观察威胁
        |
        v
FSM 执行：起步 -> 移动 -> 停止
```text

## 十一、调试面板应该显示什么

至少显示：

- 当前选中的行为和持续时间
- 所有候选的原始分与调整分
- 每个 Consideration 的输入和曲线输出
- 当前惯性、冷却和切换成本
- 本次重新评估的触发原因
- 候选不可用的明确原因

Kevin Dill 与 Dave Mark 对数学建模的进一步讨论也强调了模块化 Consideration 和复杂决策建模的可复用性[^3]。没有这些可视化数据，Utility AI 会变成一组只能靠感觉修改的数字。

## 十二、自查清单

- 所有输入是否被归一化到一致尺度？
- 每条响应曲线是否有清晰的业务含义？
- 合成公式是否公平处理不同数量的 Consideration？
- 硬约束是否会让候选明确失效？
- 是否有惯性、冷却或切换成本防止震荡？
- 数据错误是否明确暴露，而不是返回 0 分？
- 日志能否解释每个候选为什么得到当前分数？
- 评分器是否只负责选择，而不直接操作动作系统？
